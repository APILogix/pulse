# Request ingestion

Status date: 2026-08-27.

## Write path

`ingest.request` writes set-based rows to `events_requests`. The writer supplies 47 fields; PostgreSQL supplies timestamps/defaults and generated request-classification columns. Typed data and eligible outbox rows remain in one transaction.

The SQL shape varies for duplicate and outbox-eligibility branches, so no universal fixed statement total is asserted.

## Generated columns

`is_slow` and `is_error` are generated by PostgreSQL and intentionally omitted from the INSERT. This preserves the deployed database contract and avoids supplying generated values from application code.

## Enrichment

The writer starts optional GeoIP reader initialization without blocking the first insert on file open/dynamic import. Before the reader is ready, IP hashing and user-agent parsing remain available while geo fields can be NULL. The row also extracts method/status/duration, route/endpoint, trace/session/user/tenant IDs, service/framework/release, sizes, tags/metadata, and normalized payload.

This asynchronous initialization reduces a potential cold-path wait structurally; no measured latency improvement is claimed.

## Fast-path outbox eligibility

`isFastPathSignal()` treats a request as eligible when it has status 401/403, another status ≥400, or a finite duration at/above `INGESTION_FAST_REQUEST_MIN_DURATION_MS` (default recorded as 1,000 ms). Ordinary successful fast requests are not eligible for the alert fast path.

This avoids creating alert handoff work for ineligible requests. In mixed new/duplicate non-error inputs, current inserted-count gating can still pass duplicate eligible inputs to outbox reservation when at least one typed row inserted; final-state idempotency remains protected, but conflict work can be amplified.

## Retry and settlement

- occurrence time and identity inputs remain stable across retry;
- conflict handling determines inserted count;
- only inserted rows are billed;
- cancellation before COMMIT rolls back typed/outbox work; and
- pg-boss completion remains downstream of successful COMMIT and post-COMMIT accounting.

## Public ID

`REQ-` IDs normally come from the sequence-backed column default, which executes before the BEFORE trigger. The trigger repairs explicit NULL/empty values and other contract fields; it is not the ordinary omitted-ID allocator.

## Evidence gaps

- production fast-path eligibility ratio;
- GeoIP cold/warm behavior under load;
- enrichment CPU per request;
- mixed-duplicate outbox overhead; and
- representative request latency/WAL distributions.
