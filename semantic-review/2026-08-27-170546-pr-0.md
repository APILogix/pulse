## HTTP acceptance and the DLQ begin at different boundaries

`processIngest()` calls `enqueueIngestJobs()` only when `acceptedByType.size > 0` and takes `accepted` from `result.enqueuedEvents`; controllers return 202 after that service result. An all-invalid or all-shed request can therefore return `accepted: 0` without a pg-boss insertion. The package keeps bulk-insert `null` semantics unknown rather than turning this into an unproven row guarantee.

Gateway validation/shedding errors exist before any source job and remain response data. Worker normalization rejects instead await `ingest.dlq-intake`, and a failed intake send fails the source job, preserving the documented gateway-versus-worker DLQ boundary.

## Forward and rollback retain the same fail-fast lock session

Forward discovery/filtering precedes checkout; the retained client then obtains `pg_try_advisory_lock`, may create `logdb_migrations`, and reads ledger state before dry-run skips migration SQL. Dry-run therefore omits the drain assertion, duplicate scan, local lock timeout, index DDL, and ledger insert but is not side-effect-free.

Rollback reads the down file first, then retains one client through lock acquisition, target lookup, down SQL, unlock, and release; confirmation refusal reaches `finally`. Both commands share the key and fail immediately on contention, while actual concurrent-process and live forward/down behavior remain explicitly unrehearsed.

## Usage accounting has two post-commit loss windows

`EventProcessor` commits typed telemetry and its outbox before incrementing the process-local `UsageCounter`. Process death before a successful staging insert can lose the increment, and duplicate redelivery cannot reconstruct it after the typed row is suppressed.

`usage_counter_staging` is `UNLOGGED`, so successful staging closes only the memory window. PostgreSQL crash recovery/restart or standby failover before rollup can still lose staged rows; the package does not present graceful shutdown or application restart alone as a durability fix.

## Settlement and identity invariants remain accurately bounded

Worker completion follows the Log DB commit. Fairness deferral awaits replacement enqueue, failures produce retryable per-job outcomes, and stable receipt time, generated identity, and occurrence time preserve retry convergence. Typed rows and `telemetry_outbox` remain transactionally atomic, usage counts inserts rather than receipts, public-ID machinery remains untouched, and migration 030 adds only the scoped log identity guard.

The package retains the material caveats: fairness is process-local, outbox reservations are organization-wide by signal/event ID, log projects remain nullable, and non-error partial duplicates can amplify outbox work.

## Evidence and working-tree provenance stay within execution history

The benchmark artifact is a 3,564-case dry-run plan with zero completed cases. The package says `BENCHMARK NOT EXECUTED`, leaves the exact five-column duplicate count unknown, marks live migration/rollback and concurrency rehearsal unverified, and reports no queue rebuild, telemetry deletion, or measured gain.

The change catalog accounts for the current evidence scripts, helpers, focused tests, migrations, task files, and eleven ingestionv2 documents. It distinguishes the latest ingestion/lifecycle/lock corrections from preserved evidence/spec work and treats semantic reviews as review output rather than implementation evidence.
