# Retry-safe ingestion startup and scoped Log DB identity hardening

This follow-up closes the prior review’s trace prototype bypass, log identity scope collision, live-index rollout gap, failed registration retry gap, and failed-only admission diagnosis gap. Telemetry success still reaches pg-boss only after the Log DB transaction commits, while validation rejects and fairness deferrals await durable replacement queue writes. One new rollback regression remains: a failed worker replica can remove the shared usage-rollup schedule used by healthy replicas. Watch for: fleet-wide rollup scheduling being disabled by one failed startup (**medium, confirmed**).

**Verdict**: NEEDS_CHANGES

## High-level view

UsageRollup and WorkerRegistry now share concurrent startup attempts, retain registrations until `offWork` succeeds, and block replacements behind retry cleanup. Schedule cleanup is different because pg-boss schedules are global by queue name and schedule key; the new failed-start cleanup can delete the fleet’s valid schedule.

The durability boundary is unchanged: validation DLQ sends, fairness copies, telemetry/outbox writes, and `COMMIT` are awaited before completion. Per-job retries and the per-tenant defer/aging gate remain active.

Trace validation and persistence now reject inherited child trees, failed-stage admission waits participate in diagnosis, and log identity includes organization/project/environment scope. The non-concurrent log index is fail-closed behind a populated-table drain assertion and does not delete rows.

## Failed replica rollback removes the fleet-wide usage schedule

`UsageRollup.startInternal()` marks `scheduleMayBeRegistered` before `pgboss.schedule()` and cleans up every scheduling error (`src/modules/ingestion/workers/usage-rollup.ts:138-150`); cleanup calls `pgboss.unschedule(INGEST_USAGE_ROLLUP_QUEUE)` (`usage-rollup.ts:158-161`). In pg-boss 12.22, the schedule is a database row keyed by `(name, key)`, and `unschedule(name)` deletes the shared default-key row rather than process-local state.

This is a **medium-severity, confirmed** regression. During a rolling deployment, a replica with an invalid cron fails before writing anything, then deletes the valid schedule created by healthy replicas. No new rollup jobs appear until another successful startup recreates it, delaying entitlement and daily billing updates while staging accumulates. The test expects `unschedule` after a rejected `schedule` (`src/modules/ingestion/workers/usage-rollup.test.ts:55-64`), locking in that behavior.

Rollback should unregister only the local rollup worker. Provision the shared schedule separately or assign it to one coordinator, and test that a failed replica leaves an existing schedule intact.

## Registration cleanup and fairness remain retry-safe

WorkerRegistry removes a queue from `registeredQueues` only after `offWork(..., { wait: true })` resolves (`src/modules/ingestion/workers/worker-registry.ts:207-213`). Retry preflight runs retained cleanup before provisioning and throws before replacement registration when cleanup still fails (`worker-registry.ts:220-224`).

The fairness path awaits the deferred copy’s `pgboss.send()` before completing the original (`worker-registry.ts:406-423`), while admitted work awaits `processor.process()` (`worker-registry.ts:441-445`). A copy-enqueue or processing failure therefore remains a retry, and the organization defer/aging gate is still present.

## Durable commit and scoped idempotency

Validation rejects await DLQ enqueue at `src/modules/ingestion/workers/event-processor.ts:359`. Telemetry and outbox rows share a transaction whose `COMMIT` is awaited at line 523; `process()` returns at line 655, and WorkerRegistry awaits it before returning a completed disposition. No changed path acknowledges telemetry before durable commit.

The `events_logs` index now uses `(organization_id, project_id, environment, event_id, occurred_at)`, matching the generated identity’s tenant stream (`database/migrations/logdb/03_observability_v2/030_events_logs_idempotency.up.sql:44-70`). `ON CONFLICT DO NOTHING` remains in the writer, so the change fixes cross-scope collisions without weakening retry deduplication.

## Trace, diagnosis, and migration safeguards

Trace roots and children use null-prototype clones (`src/modules/ingestion/pipeline/event-normalizer.ts:348,427`), and normalization reads only an own `children` property at line 381. Persistence repeats that check at `src/modules/ingestion/pipeline/telemetry-writer.ts:1214`, closing the JSON `__proto__` inherited-subtree path.

Worker diagnosis takes the maximum successful/failed `writeAdmissionWaitMs` p95 before thresholding (`scripts/summarize-ingestion-worker-profiles.ts:345-365`), so failed-only saturation no longer reports no bottleneck.

The log migration requires an operator drain assertion on populated tables (`030_events_logs_idempotency.up.sql:26-36`), runs a scoped duplicate preflight, and creates only the unique index. The auto-discovered up migration contains no row deletion; the excluded down migration gates dropping the new index behind the same assertion. No destructive live data operation was added. Actual PostgreSQL lock behavior was not exercised in this pass.
